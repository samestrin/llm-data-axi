## [2.0.2] - 2026-11-23

### Security

- **An MCP tool value can no longer act as a CLI option.** The server passed tool values such as a `yaml_multiset` key, a `grep` pattern or a `catfiles` path to the CLI as bare arguments, so a value spelled like an option was read as one: the pair `{"--file=h.yaml": "--create"}` wrote `h.yaml`, a file the caller never named. Every value built from tool input now follows a `--`, and the encoding flags go before it. A `grep` pattern such as `-v` can now be searched for over MCP.
- **The MCP `template` tool no longer reads files named in `vars`.** Each `vars` value went to the CLI as `--var KEY=VALUE`, and the CLI reads a value starting with `@` as a file path, so `{"k": "@sec.txt"}` returned the contents of `sec.txt` to a caller that never opted in. The server now passes the new `--literal-vars` flag, which takes every `--var` value as given, and the tool description says so. On the CLI, `--var KEY=@PATH` still reads PATH.

### Fixed

- **`yaml set` and `yaml multiset` keep the file's mode and follow a symlink.** A write replaced a 0644 file with a 0600 one, and replaced a symlink with a regular file while its target kept the old value, still reporting `status: set`. The target is now written and keeps its mode.
- **`yaml set` and `yaml multiset` refuse a key that names no value.** An empty key, `a..b`, a leading or trailing dot, an unclosed `[` or an empty `[]` printed `status: set` with exit 0 and wrote nothing or the wrong key. They are now a usage error (exit 2) and nothing is written.
- **`yaml set` keeps the comment on the line it edits.** `port: 1 # keep` came back as `port: 2`; it is now `port: 2 # keep`.
- **Reading YAML no longer creates files.** `yaml get`, `yaml multiget` and `--dry-run` left a 0-byte `<file>.lock` (and `..lock` for `yaml get --file .`). Reads and dry runs take no lock now, and on Linux and macOS a write removes its lock file when it finishes. On Windows the lock file is left behind: Windows will not remove a file another handle has open, and the lock is held while it is removed.
- **No command hangs on a FIFO or a device.** `catfiles`, `template` and `count --mode lines` read `/dev/zero` without end, and `grep`, `catfiles`, `count -r` and `multigrep` blocked forever on a FIFO in a directory. A FIFO, device or socket named outright is an error (exit 1, `not a regular file`); one found in a directory is skipped and reported: `non_regular_skipped` in `grep` and `multigrep`, `skipped` in `count` and `catfiles`.
- **`template -o` and `multigrep --output-dir` refuse a target that is not a regular file.** `template -o` on a FIFO hung, and a FIFO at a `multigrep` keyword file name hung the run; a symlink there was written through and overwrote the file it pointed at, a source file in the probe. The target is checked without following it: a new path or a regular file is written, and a FIFO, device, directory or symlink is refused before anything is written. `template` exits 2; `multigrep` exits 1 with the refused files in `failed_writes` and writes none of the keyword files.
- **`yaml set` and `yaml multiset` keep comments and key order when they add a key.** A new key whose parents did not exist yet, a key with an escaped dot, a key in a file holding only comments, and any `multiset` batch with a hyphen in a key (`my-key`) re-encoded the whole file: every comment, the header included, was dropped and the keys were sorted. The key is now inserted into the existing document, with any missing parents, after the keys already there. A key inside an array or below a scalar still takes the old path.
- **`template --var` with no `=` or no key is a usage error (exit 2).** `--var k` and `--var =x` were dropped without a word and the template rendered with exit 0.
- **`catfiles` reports what it left out on stdout.** A stop at `--max-size` and a skipped binary file went to stderr only, so stdout read as complete. The result now carries `truncated`, `not_read`, a `skipped` list of `{path, reason}` and a `help` line.
- **Invalid flag values are usage errors (exit 2).** `count --mode bogus` exited 1, `highest --type bogus` ran as `both`, `tree --depth -1` printed an empty tree, `git-context --max-commits -3` returned every commit and `catfiles --max-size 0` printed no files, all but the first with exit 0. `count --style` and `tree --max-entries` are checked too.
- **`multigrep` labels matches in a file with that file's path.** With `--path` naming a file, every match was labelled `.`.
- **`multigrep --output-dir` writes each keyword to its own file.** `a b` and `a_b` both became `keyword_a_b.txt`, and the second overwrote the first. A keyword that is not a safe file name now gets a short hash in its file name, and `output_files` maps each keyword to its file.
- **`setup` writes the bare `llm-data` into a hook only when PATH finds this binary.** Any `llm-data` on PATH was taken to be this one, so the hook could run another build. Otherwise the hook names this binary's absolute path.
- **Usage errors say what to pass.** Every exit-2 error carries a `help` list with the missing flag and what it takes, the usage line and the command's `--help`; `--plain` prints it under the message. `count` without `--mode` is now a usage error. `git-changes` outside a repository names the directory instead of repeating git's "or any parent up to mount point".
- **`grep` and `catfiles` skip `.git`.** A search of a repository matched git's own files and listed `.git/index` and every pack in `binary_skipped`. `--no-gitignore`, or naming `.git` itself, still searches it.
- **Every command's `--help` has examples, and its field names match the output.** `count`, `detect`, `stats`, `catfiles`, `grep` and five more had none; `count --help` described `TOTAL: N` while TOON prints `count:`, and `detect`, `discover-tests` and `multiexists` listed upper-case fields the output does not have. `grep`, `catfiles` and `multiexists` show their required arguments as required.

### Changed

- **The MCP `template` tool's default syntax is documented.** It defaults to `[[var]]` placeholders while the CLI defaults to `{{var}}`; the tool description, its `syntax` field and the README now say so. The default itself is unchanged, so existing MCP clients keep working.
- **The skill says how to install llm-data and what a failure looks like.** It names `go install` and `go run` lines for the release, the `error: true` / `message` shape, exit codes 1 and 2, and `truncated` and `--full`.
- **`benchmarks/RESULTS.md` names the binary and the commit it was measured at.** The generator records the `llm-data --version` output and each repository's commit, and refuses to write the report from a checkout with uncommitted changes. The committed table is regenerated from a clean checkout.
- **The committed performance results are from this release's binary.** `benchmarks/results-performance.json` and `.md` were measured on 1.1.0, then on the v2.0.1 release build after it was tagged; they are now measured on the 2.0.2 release candidate, built from the commit to be tagged and stamped with its version, so the tag carries its own figures. A test fails when the committed results name a version other than the latest release in this changelog.
- **The release documentation is updated before the tag, not after.** v2.0.1's own README pinned v2.0.0 and its audit cites were off, because both were corrected only after tagging. The checklist now regenerates the token and performance results and re-checks the README, the audit and the catalog entry on the release candidate before the tag. The README install, quick-start, source and configuration examples pin v2.0.2. Documentation only.
- **The README says what ships and what it reads.** It names both binaries, says the MCP server's 20 tools are every command but `setup`, gives the `npx skills add ... --agent claude-code -y` form for a session without a terminal, notes that `template --var KEY=@PATH` and `--env` read files and environment variables you name, and its `highest` example uses a path that exists. Documentation only.
- **The AXI audit and catalog entry describe v2.0.2.** `docs/axi-audit.md` was re-probed on the release candidate and its line citations re-checked; it now names `grep`'s `unreadable` list under principle 6 and says the skill is a hand-written constant. The catalog entry's observations and token figures match. Its `reviewed_revision` still names v2.0.1 until v2.0.2 is tagged. Documentation only.

## [2.0.0] - 2026-11-18

### Added

- **Performance benchmark.** `go run ./benchmarks -perf` times `llm-data` for three cases: cold start (`--version`), a typical command (`detect --path .`) and a large input (`stats --path .` over at least 3,000 files: `BENCH_DIR`, or a generated directory when it is unset). It writes every raw timing to `benchmarks/results-performance.json` and the table to `benchmarks/results-performance.md`, whose header names the version, date, machine and method; `-perf -from-json` regenerates the table from the JSON alone. A case that fails, prints nothing or records no timing exits non-zero and writes nothing. The committed result was from the v1.1.0 release binary.
- **`llm-data setup --target` names the agents to register with.** It takes a comma-separated or repeated list; the default is `claude`, so a bare `llm-data setup` writes what it did before. An unknown target is a usage error (exit 2) and nothing is written.
- **`llm-data setup --target codex` registers llm-data with Codex.** It merges the SessionStart hook into `.codex/hooks.json` and sets `[features] hooks = true` in `.codex/config.toml`, keeping every other hook, key and comment. The hook command is chosen and repaired exactly as for Claude Code, and `--dry-run` reports both files without writing. A `config.toml` that cannot be changed by a line edit alone (invalid TOML, or `features` as a dotted key or inline table) is refused and nothing is written. The default target is still `claude` alone.
- **`llm-data setup --target opencode` registers llm-data with OpenCode.** It writes a plugin at `.opencode/plugins/llm-data.js` that runs `llm-data` once per session and adds the home view to OpenCode's system context, under both OpenCode 1 and OpenCode 2; it adds no tool, and a home view that fails adds an error line instead of nothing. The command is chosen exactly as for Claude Code and Codex, and a plugin naming a binary that has since moved is rewritten. A second run changes nothing, `--dry-run` writes nothing, and a file at the plugin's path that `setup` did not write is refused and nothing is written. The default target is still `claude` alone.

### Changed

- **The Go module path is now `github.com/samestrin/llm-data-axi/v2`.** **Breaking** for Go importers: update imports and `go install` commands to include `/v2`.
- **`multiexists` with a missing path prints one error document.** It printed the full result and then a second, error document, so a JSON parser failed on the very case `multiexists` exists to report. It now exits 1 with one error whose message names the missing paths, plus `missing`, `exist_count` and `missing_count` in TOON and `--json`. **Breaking** for a caller that read `entries` from a failed run: pass `--no-fail` for the full listing with `all_exist: false` and exit 0 (the MCP tool already does).
- **Command output is now TOON by default instead of plain text.** Every command emits token-dense TOON when no output flag is given; `--axi` still explicitly selects TOON and `--json` still selects JSON. **Breaking:** callers that need the previous plain-text output must now pass `--plain`.
- **Conflicting output flags are rejected.** Combining `--plain` with `--json` or `--axi` is now a usage error (exit 2) that names the conflicting flags, instead of silently choosing one output format.
- **The skill `setup` writes says TOON is the default output.** It told agents to add `--axi` for TOON; it now says output is TOON by default and `--plain` gives text. The committed `skills/llm-data/SKILL.md` matches.
- **Breaking (v2.0.0): `tree`, `stats`, `multigrep`, `grep`, `catfiles`, `highest` and `git-context` print paths relative to the working directory by default; for `git-context`, this means `repository.path` and `repository.root`.** Pass `--absolute` to restore the previous absolute paths. Paths outside the working directory stay absolute, and `repo-root` still prints an absolute root.

### Removed

- **`plan-type` is removed.** Use `cadence plan type` instead.
- **`project-components` is removed.** Use `cadence plan components` instead.
- **`tier-classifier` is removed.** Use `cadence tier classify` instead.
- **`diff-smell` is removed.** Use `cadence diff smell` instead.
- **The MCP tools `plan_type`, `project_components`, `tier_classifier` and `diff_smell` are removed with their commands.** A call to one fails with the same error the CLI prints, naming the cadence replacement.

### Fixed

- **Every subcommand's `--min` help says it has no effect on TOON.** `stats`, `grep`, `catfiles`, `tree`, `template`, `multiexists`, `math`, the `yaml` subcommands and nine more still described `--min` as "Output in minimal/token-optimized format" or "Minimal output - just the value", though `--min` changes nothing under the TOON default. The flag works as before under `--json` and `--plain`; `math --min` only changes `--plain` output, and its help now says so. The `yaml get` and `yaml multiget` help named their plain text as the default and gave a bare `--min` example that prints TOON key and value; they now name TOON as the default and the example passes `--plain --min`.
- **The docs match the v2.0.0 command set and path output.** The README command table, the AXI audit, the catalog entry, the demo docs and the release checklist drop the four workflow commands (the README keeps one migration note naming their cadence replacements) and the absolute-path caveat: paths are relative to the working directory by default, so the demo no longer depends on where it is rendered. `benchmarks/RESULTS.md` is regenerated and its totals no longer shift with the checkout location; the catalog's token figures match it. Documentation only.
- **A wrong argument count is a usage error, exit 2.** `yaml set --file c.yaml a`, a bare `math` and `grep onlyone` exited 1, as if the command had run and failed, while a missing required flag exited 2. Every argument-count error now exits 2.
- **`catfiles` on an empty directory reports zero files instead of failing.** It exited 1 with `no files found` though nothing had failed. It now exits 0 with `file_count: 0` and `total_size: 0` (`FILES: 0` under `--plain`). A path it cannot read is still an error.
- **`stats` and `tree` state their counts on an empty directory.** `stats` dropped `files`, `directories` and `by_extension`, and `tree` dropped `total`, so a zero read as a missing field. They now print `files: 0`, `directories: 0`, an empty `by_extension` and `total: 0`.
- **The README and the AXI audit match the code.** The README title is `llm-data-axi` and its command list includes `setup`; the audit's `multigrep` line references point at the current lines. Documentation only.
- **The 1.0.2 section is folded into 1.1.0.** It was cut on 2026-11-09 but never tagged, so its changes first shipped in 1.1.0. Documentation only.
- **`template --strict` fails on an undefined variable.** It printed `ERROR: Undefined variable: x` on stderr and then `status: success`, exit 0. It now exits 1 with `undefined variables with --strict: x` on stdout in the active format, plus an `undefined` list in TOON and `--json`; with `--output` the file is not written. A variable with a `{{name|default}}` still counts as defined.
- **`catfiles` fails when it cannot read something it was asked for.** A file it could not read was dropped with a stderr warning, and a file it could not stat (such as a dangling symlink) or an unreadable subdirectory was dropped with no message, all with exit 0. It now exits 1 naming each path and why, plus an `unreadable` list of `{path, reason}` in TOON and `--json`. Binary files are still skipped as before.
- **`multigrep --output-dir` fails when a keyword file cannot be written.** It warned on stderr and exited 0 while stdout reported the matches as if the files existed. It now exits 1 naming each file and why, plus a `failed_writes` list of `{file, reason}` in TOON and `--json`.
- **Errors are printed on stdout in every output format.** Runtime and usage failures now use the command's selected format—TOON by default, JSON with `--json`, or plain text with `--plain`—so a caller reading stdout always receives the error instead of an empty stream. Existing exit codes are unchanged, and stderr remains reserved for diagnostics.
- **A bad flag value says what the flag takes.** `llm-data runtime --start abc` reported `invalid argument "abc" for "--start" flag: strconv.ParseInt: parsing "abc": invalid syntax`. It now reports `invalid value "abc" for --start: want an integer` (or `true or false`, `a number`, `a duration such as 30s or 5m`, or `integer out of range`), still exit 2. A custom value such as `setup --target` keeps its own reason. A `--json` or `--plain` given after the bad value is now honoured: the error used to come out as TOON.
- **An unknown flag's valid flags are data.** The TOON and `--json` error now carries a `valid_flags` list next to the message, so a caller no longer splits the sentence to read them. The message still lists them.
- **The home view's git timeout names the call that timed out.** Both git calls shared one 2-second budget, but the message always said `no answer within 2s`, even for a `git status` left a fraction of it. Each call now has its own 2 seconds, and the message says which call gave no answer, such as `git status gave no answer within 2s`.
- **`--version-upper` is no longer an accepted spelling.** It existed only because pflag needs a long name for `-V`, and nothing documented it. `-V` still prints the version; `--version-upper` is an unknown flag (exit 2).

- **`setup` no longer registers a hook the session cannot run.** The Claude Code SessionStart hook was always the bare `llm-data`, which fails when the binary is not on `PATH`. It is now the bare command only when `PATH` finds it, and otherwise the absolute path of the binary that ran `setup`. A hook `setup` wrote earlier that no longer matches (the old path after the binary moved, or a bare command once `llm-data` leaves `PATH`) is rewritten in place, and a second llm-data hook is removed. With neither, `setup` fails and writes nothing.

- **`go install` builds report the installed version, not a stale `1.0.0`.** `llm-data` and `llm-data-mcp` defaulted their version to the literal `1.0.0`, which only a build-time stamp replaced, so a `go install` of `v1.1.0` (which runs no stamp) claimed release `1.0.0`. The default is now `dev`, and when no stamp is present both binaries read the module version Go recorded in the binary, so a `go install` of `v1.1.0` reports `1.1.0`. A release build's stamp still wins, and a build with no recorded module version reports `dev`.

- **`grep` no longer runs out of memory on a file with no newlines.** `llm-data grep x /proc/self/pagemap` read the whole file as one line until the process was killed. A line over 64 MiB is now an error naming the file and the line, and the run exits 1. A binary file (a NUL byte in its first 8000 bytes) is skipped rather than searched, and the skip is reported: `binary_skipped` in `--json` and `--axi`, and a `binary skipped: <path>` line above `total:` in plain output (the first five by name, then a count).
- **`repo-root` and `git-changes` say "not a git repository" only when git says so.** `repo-root` reported any git failure, including git missing from `PATH`, as `ERROR: not a git repository` and exited 0, and `git-changes` gave every failure of its repository check the same label. Now only git's own answer gets that label. Any other failure exits non-zero with its own reason, such as `git not found in PATH` or git's last line of stderr.
- **`math` reports a non-finite result as an error in every format.** `llm-data math "1/0" --json` printed an empty line and exited 0, `--axi` failed with the encoder's internal `json: unsupported value: +Inf`, and plain printed `RESULT: +Inf` with exit 0. A result that is `+Inf`, `-Inf` or `NaN` (`1/0`, `0/0`, `sqrt(-1)`) now exits 1 with a structured error naming the expression and the value: `math: 1/0: result is +Inf: division by zero or overflow`, `math: 0/0: result is NaN: not a number`.
- **`yaml get --json` and `yaml set --dry-run --json --min` no longer print an empty line for a `.inf` or `.nan` value.** JSON cannot encode those values, and the encoding error was dropped, so the command printed nothing and exited 0. It now exits 1 with an error naming the key and the value. The same dropped error is fixed in `math`, `git-changes` and `setup`.
- **`repo-root` outside a repository states a fact instead of an error.** It exited 0 while printing `ERROR: not a git repository` (plain), an `error` key (`--json`) or `error: not a git repository` (`--axi`), so the payload said failure and the exit code said success. Exit 0 is kept, and the answer is now `git_repository: false` in the default TOON output and in `--json`, and `GIT_REPOSITORY: FALSE` with `--plain`; inside a repository TOON and `--json` carry `git_repository: true` beside `root`. Breaking for a caller that read the `error` key.
- **`git-context` says "not a git repository" only when git says so.** Its repository check reported every git failure, including a dubious-ownership refusal or a broken config, as `not a git repository`. Any other failure now exits 1 with git's own reason, and git missing from `PATH` reads `git not found in PATH`, as in `repo-root` and `git-changes`.
- **`llm-data-mcp` refuses to start when `llm-data` is a directory or not executable.** Startup rejected only a missing path, so `LLM_DATA_BINARY` pointing at a directory or at a file without the exec bit started the server and every tool call then failed. It now exits 1 with `llm-data binary at <path> is a directory` or `... is not executable`, followed by the same lookup help as a missing binary.
- **`grep` fails when it cannot read a file it was asked to search.** A file it could not open (mode 000, a dangling symlink) and an unreadable subdirectory were skipped without a word, so `total_matches: 0` and exit 0 read the same as a search that found nothing. It now exits 1 naming each path and why, plus an `unreadable` list of `{path, reason}` in TOON and `--json`, as `catfiles` does. A directory `.gitignore` excludes is still not searched and cannot fail the run.
- **An MCP tool call whose command fails is an error result.** `llm-data-mcp` sent a command's non-zero exit as a success (`isError: false`), so a client checking `isError` was told a grep of a missing path worked. It now sets `isError: true` and still passes the CLI's own error output as the content.
- **The README matches v2.0.0.** It pinned `v1.1.0` in its install, quick start and configuration examples, described plain text as the default output and errors on stderr, omitted `--plain`, and named only the Claude target for `setup`. It now pins `v2.0.0`, documents TOON as the default, `--plain`, errors on stdout in every format and `setup --target claude|codex|opencode`. Documentation only.
- **The `llm-data-mcp` server reports its release version.** The version was a constant, which the build's `-X main.serverVersion` stamp cannot set, so every release told MCP clients it was `1.0.0`. It is now stamped, and reported without the tag's leading `v`, as `llm-data --version` reports it.

## [1.1.0] - 2026-11-13

This release also carries the changes once listed here as 1.0.2 (2026-11-09). That section was cut but never tagged, so they first shipped in 1.1.0 and are folded in below.

### Added

- **A bare `llm-data` shows the repository it runs in.** Next to `bin:` and `description:` the home view now prints `repo_root:`, `project_type:` and `git_changes:`, from the same logic as `repo-root`, `detect` and `git-changes`. Outside a repository it says `repo: no repository`, and only when git itself reports that; git missing, a git error or no answer within 2 seconds prints `repo: git unavailable: <reason>` instead. The run exits 0 in every case. `--json` and `--axi` carry the same fields plus `help[]`.
- **An installable Agent Skill is committed at `skills/llm-data/SKILL.md`.** `npx skills add samestrin/llm-data-axi --skill llm-data` installs the same skill `llm-data setup` writes into a project's `.claude/skills/`. A test runs `setup` and fails if the committed file and the text it writes differ by a byte, so the two can never drift apart.

### Changed

- **`-v`, `-V` and `--version` print the bare version and exit 0.** A release build prints `1.1.0`, not `llm-data version v1.1.0`. Breaking: `-v` used to be a root `--verbose` that no command read, and `-V` was an unknown flag.
- **The root `--verbose` and `--format` flags are gone.** Nothing read either, so `grep x . --verbose` ran as if the flag were absent; it is now an unknown-flag usage error. `multiexists --verbose` and `runtime --format` keep their own flags.
- **`multiexists` drops the `-v` shorthand for `--verbose`.** `multiexists -v` is now rejected as an unknown shorthand flag; use `--verbose`.

- **CI runs the installer harness on macOS too.** A `installer-darwin` job in `install.yml` builds the release directory and runs `tests/install/run.sh` on `macos-latest`, so the Darwin path — where curl sets no quarantine flag and Go links an ad-hoc signature on arm64 — is actually executed on every push instead of never.
- **`grep` truncates matching lines with a size hint and a `--full` escape hatch, and reports a match total in every mode.** Lines over 200 bytes are cut in plain, `--json` and `--axi` alike, with `truncated`, `full_length` (the whole line's size) and a `--full` next step; `--full` returns the whole line. `total_matches` is always emitted — including `total: 0` in plain mode, which used to print nothing at all — and counts matching lines, or files with `-l`.
- **`multigrep` truncates content in every mode and always states its counts, including 0.** The 80-character cut used to apply in plain mode only, so `--json` and `--axi` emitted whole lines; it now applies everywhere, is marked, and `--full` opts out. `total_matches`, `match_count`, `keywords_with_matches`, `keywords_searched` and `files_searched` lost their `omitempty`, so a zero reads as an explicit `0`, not an absent field.
- **`git-context --full` returns the whole diff instead of cutting it at 50,000 bytes.** The cut itself is unchanged and still says so.
- **README Install shows the pinned-release command with the variable on the `sh` side of the pipe** (`curl -fsSL .../install.sh | LLM_DATA_VERSION=v1.0.0 sh`). Written as `LLM_DATA_VERSION=v1.0.0 curl ... | sh` the variable reaches `curl`, not `sh`, and the pin is silently ignored. Documentation only.
- **The AXI audit's finding 6d is struck and its subcommand counts corrected.** `yaml push` was deleted in epic 5, so the idempotency finding no longer describes this tool; the audit now lists the 4 live `yaml` subcommands instead of the 10 it probed at audit time. Documentation only.

### Fixed

- **`llm-data-mcp` finds `llm-data` beside its own executable when it is not on `PATH`.** The lookup now tries `LLM_DATA_BINARY`, then `PATH`, then the directory of the running `llm-data-mcp`, then `/usr/local/bin/llm-data`, so the installer's default `~/.local/bin` works without a `PATH` entry. A sibling that is a directory or lacks the exec bit is not reported as found. When the binary is nowhere, the startup error names the path tried, the sibling location and `LLM_DATA_BINARY` instead of a bare "not found".
- **Usage errors are structured on stdout under `--axi` and `--json`.** `llm-data grep --nope --axi` used to print plain text on stderr; it now prints a TOON (or JSON) error on stdout, nothing on stderr, still exit 2, and an unknown flag's message names it and lists the command's valid flags.
- **`multigrep --json --min` no longer prints a zeroed long count beside its short alias.** Since the explicit-zero change above, minimal output carried `"tm":2` next to `"total_matches":0` (and the same for `ks`, `kwm`, `fs`), and the MCP server sends `--json --min`. Minimal output now carries only the short aliases; full output still states every count, including 0.
- **`multigrep`'s plain-mode `(long lines truncated; rerun with --full)` hint shows only under a keyword whose own lines were cut.** It used to print under every keyword, including ones with 0 matches, whenever any keyword had a cut line.
- **`grep` and `multigrep` no longer split a multi-byte character at the truncation cut.** The 200-byte (`grep`) and 80-byte (`multigrep`) cuts sliced at a raw byte index, so a line whose cut fell inside a character like `é` emitted half of it: `--json` showed `\ufffd` and the text was not the line's real prefix. The cut now backs off to the previous character boundary and still ends in `...`; `full_length` is unchanged.
- **Plain `grep` prints the `--full` hint when a line was cut.** The hint was only in `--json` and `--axi`, so a plain cut line ended in a bare `...` that read like content. It now prints `Whole lines: rerun the same grep with --full` after the matches, and only when a line was cut.
- **`git-context` no longer splits a multi-byte character when it cuts a large diff at 50,000 bytes.** The diff cut sliced at a raw byte index, so a diff whose 50,000th byte fell inside a character like `é` emitted half of it: `--json` showed `\ufffd` and plain/`--axi` wrote invalid UTF-8. The cut now backs off to the previous character boundary, the same fix the 200-byte (`grep`) and 80-byte (`multigrep`) line cuts already had.
- **`multigrep -d` no longer offers `--full` for a line it did not show.** In definitions mode the plain printer hides usage matches, but the truncation hint counted them, so a short definition plus a long usage printed `(long lines truncated; rerun with --full)` even though no displayed line was cut and `--full -d` changed nothing. The hint now reflects only the displayed matches.
- **`multigrep` cut lines carry `full_length`, like `grep`.** A cut match said `truncated` but not how much of the line was missing; it now also states the whole trimmed line's byte count, so a caller can decide whether `--full` is worth it. Uncut and `--full` lines carry neither field.
- **`grep` finds matches on lines longer than 64 KiB.** A matching line in a minified or generated file stopped the scan, so `llm-data grep needle min.js --full` printed `total: 0` and exited 0. Lines of any length are now read whole, every later line is still searched, and a read that fails part-way is an error naming the file instead of a short result.
- **`multigrep --output-dir` writes whole lines again.** Since the 80-byte cut moved into the search, the `keyword_*.txt` files held cut lines with no marker. They now carry each matching line whole, while stdout is still cut unless `--full` is given.
- **`multigrep -d --json` and `-d --axi` offer `--full` when a usage row was cut.** Those encodings still emit `other_matches` under `-d`, but the hint was suppressed as if they were hidden, leaving a cut row with no next step. Only plain output, which hides usages under `-d`, leaves it out. The `--full` help now says the cut is 80 bytes, not characters.
- **The `llm-data` skill no longer names the removed `yaml list`.** The skill `llm-data setup` writes, and its committed twin at `skills/llm-data/SKILL.md`, said `llm-data yaml get|set|list`; `yaml list` is gone, so an agent following it got an unknown-command error. It now says `llm-data yaml get|set|multiget|multiset`, and a test fails if the skill names any command or subcommand that is not registered.
- **`detect` and the home view's `project_type` give the same answer on every run when a directory has more than one marker.** A repo with both `package.json` and `go.mod` could report `node` on one run and `go` on the next, because detection took the first hit from an unordered map. `stack`, `package_manager` and `framework` now check their markers in a fixed order and the first one listed wins: `package.json` before `go.mod`, `yarn.lock` before `pnpm-lock.yaml` before `package-lock.json`, and `next.config.*` before the other framework configs.

## [1.0.0] - 2026-11-03

### Changed

- **The README Install section now leads with the one-line installer** (`curl -fsSL .../install.sh | sh`, no clone, no sudo), keeps `make build` / `make install` as the build-from-source alternative, and states that support is best effort across the five release platforms (`linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`, `windows/amd64`) with no guarantee.

Each binary is then replaced atomically; a failure after that point, such as an installed `llm-data` that does not run, exits non-zero with the new binaries in place. Build from source with `make install`.

- `yaml get` and `yaml set` errors for a missing file no longer tell the caller to run the deleted `yaml init`; `set` still points at `--create`.

- **A bare `llm-data` run shows a home view instead of cobra help.** It prints two lines, `bin:` with the executable path (home directory written as `~`) and `description:` with one sentence, and honours `--json` and `--axi`. `--help` still prints help, and an unknown subcommand still fails with exit 2. If the executable path cannot be resolved the run fails rather than printing an empty `bin:`.
- go-axi moves from **v0.1.2** to **v0.3.0**.

### Fixed

- **`grep` treated a missing path as "no matches".** A path that failed `os.Stat` was skipped with `continue`, so `llm-data grep foo /nonexistent --axi` printed `pattern: foo` and exited 0, and `--json` printed `{"pattern":"foo"}`. It now fails with `path not found: <path>` and exit 1 in plain, `--json` and `--axi` modes, including when the missing path sits beside real ones.
- **`--axi` was unreachable through MCP.** `ExecuteHandler` appended `--json --min` to every command unconditionally and no handler ever passed `--axi`, so an MCP client could not obtain TOON no matter what the CLI supported. The server now sends exactly one encoding flag, selected by `LLM_DATA_MCP_AXI` or by a per-call `"format": "axi"` argument. Pinned end to end over stdio.
- **A data race in `BatchProcessor.ProcessItemsWithProgress`.** The completion counter was incremented from inside each worker goroutine with no lock. Measured under `-race` across 32 items at concurrency 8: the final progress report read "29 of 32" and three intermediate values were reported twice. The counter and the callback now run under one mutex, so the callback also sees a strictly increasing count.
- **The MCP server hardcoded `/usr/local/bin/llm-support`** with no lookup, so it refused to start for anyone who installed the CLI elsewhere, and the repo's own end-to-end tests could not run without installing first. `BinaryPath` now resolves from `PATH`, falls back to the install location, and honours `LLM_DATA_BINARY`.
- **A help-text promise that nothing kept.** `extract-relevant --help` advertised a `.planning/.config/openai_api_key` file. No such file was ever read; the LLM client configuration was environment-only. The line was corrected to name the environment variables that actually work; the command itself has since been removed (see Removed).
- **`git-context` listed remotes in a different order on every run.** The list was built by ranging over a map, so a repository with more than one remote printed them in random order. Remotes are now sorted by name, and the `git remote -v` parser is pinned by a table test over captured output.

### Not ported

Thirty-four command files stayed in `llm-tools` because no consumer calls them, and fifteen TD, temp and context tools are migrating to `cadence-axi` instead. Nothing was deleted — `llm-tools` remains live — so porting any of them later is cheap.

CI fails below 80% total coverage rather than printing a percentage and moving on. Measured cold and with the LLM environment stripped: **83.9%**.
