# AXI audit: llm-data against the ten principles

A hand audit of `llm-data` at `a9619fa` (epic 11 T1-T5 plus the flag-error and home-git-budget work of #52 merged), with the principle 6 rows for `template --strict`, `catfiles` and `multigrep --output-dir` re-probed at `1619cab`, and the rows for the AC5 review findings (principles 2-6 and 9) re-checked and their line cites refreshed, against the ten principles on https://axi.md and the integration rules in `kunchenguid/axi` `.agents/skills/axi/SKILL.md`. After epic 11.2 (v2.0.0) the rows were brought to the current command set: the four workflow commands moved to cadence and their evidence was dropped, and principle 10 was re-probed on that build. At v2.0.1 (`4cc8412`) every row was re-probed on a build of the tag and every line cite re-checked against it. For v2.0.2 every row was re-probed again on the release candidate (a build of this branch stamped 2.0.2) after the first axi.md review round, and every line cite re-checked against that source. `axi-axi` is not installed on the build host. Every probe ran against `./build/llm-data` from `make build`.

The first audit (epic 03 T1, at `e32edfe`) found principles 3, 4, 5, 7, 8 and 9 unmet and 6 partly met. Those gaps were closed by epic 03 (missing-path error, home view, `help[]`, `setup`, MCP TOON default), epic 09 (usage errors structured on stdout, live home view, committed skill) and the truncation/totals work. Epic 11 closed the last three shared gaps: TOON is the default output (T1), errors go to stdout in every format including `--plain` (T2), and `setup` registers Claude Code, Codex and OpenCode through one shared path helper (T3-T5).

**Summary:** principles 1-8 and 10 are met; 9 is partly met within a stated scope. Two remainders are stated and justified: no session-end lifecycle-capture hook (under 7) and `help[]` scoped to the home view, empty or truncated search results, a truncated `catfiles` and exit-2 errors (under 9). Both are listed below with their reason. Exit 2 for a usage error is not a gap: the spec itself asks for it ("Unknown flags must fail loud (exit 2)"; the axi skill: "0 = success (including no-ops), 1 = error, 2 = usage error").

## Remaining, justified

- **No session-end lifecycle-capture hook (principle 7).** The axi skill's integration rules recommend session-end hooks that capture what happened (transcripts, files touched, specs referenced) so future session-start context gets richer. `llm-data` keeps no session state: it is a set of deterministic, read-mostly commands with no transcript, no record of files touched and nothing of its own to capture. A session-end hook would have to invent state the tool does not have. The session-start half — the home view in Claude Code, Codex and OpenCode — is implemented.
- **`help[]` is scoped, not universal (principle 9).** `help[]` sits where a result leaves an agent without a next step: the home view, an empty search, a truncated search line or `catfiles` run, and an exit-2 error. Widening it to every command's output was deliberately left as future work when it was introduced (epic 03); it is a new task, not a defect of the existing hints.

## History

- Principle 6's verdict originally said "one stated remainder", naming only `template --strict`. Review probes (confirmed independently on a fresh build of PR #55 head `22b7773`; the probed paths — `catfiles.go`, `multigrep.go`, `template.go` — are unchanged from `a9619fa`) found two more stderr/exit-0 remainders — `catfiles` unreadable/stat-failed files and `multigrep --output-dir` write failures — so the completeness wording was corrected and both were added above with their reason. The subsequent fixes addressed all three, and principle 6 is met with no remainder.
- The AC5 review (on `4fc18a7`) found the audit overstating principles 2, 4, 5 and 6 and citing stale `multigrep` lines: `multiexists` printed two documents on a missing path, `stats`, `tree` and `catfiles` dropped their zero counts (or failed) on an empty directory, the diff-scanning command's rows carried uncut evidence and its `--diff -` waited on a terminal, and a wrong argument count exited 1. The follow-up work fixed the code for each rather than narrowing the claims, and the rows above now cite the fixes.
- Epic 11.2 (v2.0.0) moved the four workflow commands out of this binary — they are now `cadence plan type`, `cadence plan components`, `cadence tier classify` and `cadence diff smell` — and made path output relative to the working directory by default (`--absolute` restores absolute paths). The rows above dropped the removed commands' evidence rather than keeping probes of code that no longer exists here, and principle 10 was re-probed at 18 subcommands.
- At v2.0.1 the only code change since v2.0.0 is the `template --plain --min` fix (it printed minimal JSON; it now prints text), which no row cited. Re-checking the cites against the tag found the `root.go` ones 11 lines early and several `grep.go`, `multigrep.go` and `handlers.go` ones off by a few lines, already so at v2.0.0 (none of those files changed between the tags). Each now points at the line it names.
- The first axi.md review round on v2.0.1 found principle 10 overstated (no examples on five commands, field names that did not match TOON) and the principle 7 claim that the hook command was PATH-verified untrue (any `llm-data` on PATH was taken as this one); both were fixed in code for v2.0.2 rather than narrowed. The same round found an MCP option injection (a `yaml_multiset` key spelled `--file=h.yaml` redirected the write), `yaml set` false successes (malformed keys, symlinks, file mode, lock files from reads) and hangs on FIFOs and devices; each is fixed and tested, and the rows above cite the fixes.
- The original audit's finding 6d (`yaml push` not idempotent) was struck when epic 5 deleted the subcommand; it no longer describes this tool.
- The original "Not probed" note (git commands outside a repository) is resolved: `repo-root` outside a repository prints `git_repository: false`, exit 0; `git-changes` and `git-context` exit 1 naming the directory on stdout, and `git-changes` adds a `help` list (probed).
